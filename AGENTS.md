## One inquiry spine

All consequential work uses the sole model-facing recurrence defined by the construction
specification:

```text
RELATE -> OPEN -> TURN -> RETURN -> DISTINGUISH -> FOLD -> CARRY -> RELATE
```

Invoke the current derived projection with:

```text
node .claude/hooks/ic-spine.js context .
```

That command emits exactly one `QuestionPacket` for the selected executable occurrence. The
controller retains the recurrence, field, allocation, lifecycle, and closure accounting; do not
paste the whole procedure or a list of competing questions into a model prompt. `OpenObligationView`,
`QForm`, `QContract`, `AskOcc`, `QuestionPacket`, and a rendered prompt remain distinct projections.

The lifecycle trace makes `RETURN` accountable. It is not another reasoning loop. Internal helper
modules may reconstruct evidence, fields, paths, transported discriminators, folds, contexts, and
closure, but no helper may introduce a model-facing clock, fixed question sequence, semantic
scheduler, residual-to-question schedule, or residual-class-to-method dispatch.

Question forms come from ordinary partially bound relations. `Questions.txt` supplies source
renderings and pressure. The Coding section and final Reciprocal Why section remain especially
important coverage sources, but their prose order is not an execution schedule.

Questions, paths, methods, proofs, representations, and inquiry products may re-enter the same
ordinary relational language after lawful reification. Recursive formability never grants warrant.

## Branch contract and Rust boundary

The branch constructs the formal successor. Advancing predecessor Rust behavior is not its default
objective.

Until Formal Gate F is recorded as passed in `formal-successor/CONFORMANCE_STATUS.md`, do not change
Rust semantics. Preservation fixes, regression fixtures, inspection, source/schema export, and
build maintenance are allowed when they introduce no successor meaning. After Gate F, every Rust
semantic delta must derive from an explicit checked successor-to-Rust correspondence and rerun both
predecessor and successor conformance.

## Non-collapse laws

- `Generated != Actual != Supported != Warranted != Standing`.
- `Unknown != Negative`.
- Semantic coverage is not execution coverage.
- A return fiber is not a selected return.
- Question form, rendering, occurrence, contextual occurrence, path, and Answer are distinct.
- A represented path is not an actual or causal history.
- Converse is not inverse; reciprocal transport is not inversion.
- Applicability is not support.
- Current equivalence is not future protected equivalence.
- Singleton ablation is not joint ablation.
- A candidate, checker, model, fold, method, harness, or agent cannot warrant itself.
- A decisive contrast is not a localized cause until contraction and tracing establish it.
- A checkpoint is not task closure.

## Mutation and evidence

Before a consequential mutation:

- reconstruct repository actuality and the current spine projection;
- identify the live typed open position and its authority;
- state the protected difference and independent discriminator;
- construct a decisive admissible contrast or overstrong candidate when the boundary is unknown;
- seal an effectful prediction before obtaining its return.

After the return:

- preserve Raw separately from interpretation and checking;
- state exactly what was separated, excluded, supported, left plural, or left `Unknown`;
- localize the responsible relation by partition, subtraction, weakening, or backoff;
- retain only the smallest or nondominated protected deformation;
- reify products without raising their authority;
- carry new discriminators through compatible typed ancestry;
- test crossed folds and create reopening obligations;
- regenerate the field before another Ask;
- run affected checks, then broad formal and Rust preservation gates;
- update only the record that owns the resulting fact.

Append-only trace evidence is process evidence, not semantic history. Derived fields, path indexes,
contexts, reports, and caches must be deletable and reconstructible.

## Question selection and autonomy

Materialize a finite lawful field. Select only represented live executable occurrences through
explicit required-discharge, dependency, Frontier, effect, risk, coverage, resource, cost, or
supplied preference relations. Preserve every unchosen occurrence.

If incomparable occurrences remain, a stable identity tie-break may allocate execution. It does
not assert semantic optimality.

Do not ask the user to act as the routine scheduler. Ask only when a consequential protected
distinction depends on genuinely private, normative, preference-dependent, permission-dependent,
or externally unavailable information.

When no narrower task is active, continue the strongest live position in
`IMPLEMENTATION_FRONTIER.md` through the same inquiry spine until demonstrated completion or a
lawful partial outcome. A finite checkpoint regenerates and continues while resources and an
executable occurrence remain.

## Fold, method, and closure discipline

A fold requires positive protected-factorization evidence, exact members and paths, coverage,
regeneration ancestry, and a reopening condition. A supported newly carried discriminator that
does not factor through the fold reopens it. Failed factorization search leaves `Unknown`.

Methods are relational contracts over applicability, requirements, handled relations, products,
failure exits, resumption, and checks. Recurrence proposes a method fold; it does not promote one.

Task closure is coverage-relative. It requires no unresolved Ask, unreified Answer, dirty field,
open effectful return, live Required/Productive executable occurrence, unchecked relevant path
transport, or fold awaiting a carried discriminator check. Retain Blocked, `Unknown`,
ResourceBounded, inapplicable, and reopening residuals explicitly.
