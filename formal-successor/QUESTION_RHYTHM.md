# Preformal successor question programs

This is the readable projection of `ENGINEERING_QUESTION_PROGRAMS.json` and the user-supplied
`PREFORMAL_SUCCESSOR_CODING_INQUIRY_HARNESS.md`. It governs construction process only. It is not
successor semantics unless the formal successor later regenerates and warrants it independently.

## Two control levels

The repository engineering clock remains the outer work lifecycle:

```text
SPECIFY -> INSPECT -> CONTRAST -> CROSS -> LOCALIZE -> TRACE -> EXPERIMENT
-> UPDATE -> CHANGE -> VERIFY -> CHALLENGE -> MINIMIZE -> RATCHET
```

The Coding and Reciprocal Why corpora supply residual-selected inner question programs. Their
temporary vocabulary is:

```text
FRAME -> OPEN -> EXPAND -> DISTINGUISH || CONSTRAIN -> DISCHARGE -> RESOLVE
-> RECIPROCATE -> RELEASE/SUBTRACT -> FOLD/REOPEN -> OPEN
```

Neither list is a semantic opcode set. The predecessor's
`BIND -> OPEN -> VARY -> RETURN -> DETERMINE -> REFACTOR` remains predecessor behavior and a source
of pressure, not the active successor-construction rhythm. Exact typed relations outrank every
temporary label.

## The actual default questions

When no sharper residual selects a smaller principal rhythm, the harness injects and records this
compiled sequence. Each prompt is backed by stable lines in the pinned Coding corpus, but is
selected for its relational move rather than its wording.

| Position | Compiled ID | Actual question | Main relational movement |
|---|---|---|---|
| FRAME | `CQ-FRAME-FIELD` | What is here and how is it related? | establish carriers, represented relations, scope, applicability, and representation |
| OPEN | `CQ-OPEN-POSITION` | What consequential relation and which of its typed roles or ports is actually open? | distinguish a relation from its role slots and their current occupants |
| OPEN | `CQ-SHAPED-HOLE` | If this filling is removed while its typed relational position remains, what lawful completions can occupy the shaped hole and which protected distinction makes one unique? | represent absence by the retained incidence that constrains lawful fillings |
| DISTINGUISH | `CQ-LIVE-ALTERNATIVES` | Which live admissible fillings matter differently to the protected future? | identify protectedly different alternatives still merged by current observations |
| EXPAND | `CQ-STRONG-CONTRAST` | What large valid contrast makes that protected difference obvious? | bracket a boundary before attempting local minimization |
| DISCHARGE | `CQ-ACTUAL-DISCHARGE` | What actual test, proof, probe, or return can discriminate that relation without redefining it? | choose a method that answers the typed question |
| RESOLVE | `CQ-RETURN-RESOLUTION` | What did the return actually establish, exclude, leave possible, or leave Unknown? | update the live field from the return rather than the prior story |
| RECIPROCATE | `CQ-WHY-FOIL` | Why this supported result rather than the strongest still-admissible foil? | force an explicit live comparison |
| RECIPROCATE | `CQ-CARRIER` | What condition, path, role, or distinction actually carries the protected difference? | expose the proposed mechanism or delimiter |
| RELEASE/SUBTRACT | `CQ-REMOVE-CARRIER` | Can the alleged carrier be removed, reversed, replaced, bypassed, or reordered while the result remains? | attack necessity, direction, path, and role filling |
| RELEASE/SUBTRACT | `CQ-SUBTRACT-CONTRAST` | How much of the decisive contrast can be subtracted while the protected difference remains? | localize inside a known crossing |
| RELEASE/SUBTRACT | `CQ-BOUNDARY` | What survives at the boundary, and does one further removal reopen the alternative? | retain the minimal or nondominated protected distinction |
| RESOLVE | `CQ-GROUND` | What independent return grounds the surviving relation, and what would defeat it? | separate generation, return, support, check, warrant, and standing |
| FOLD/REOPEN | `CQ-FOLD` | What distinction, question, or representation can now be folded without protected loss while required regeneration remains possible? | compress only after checking protected equivalence and regeneration |
| FOLD/REOPEN | `CQ-REOPEN` | What future continuation, context, representation, or return would invalidate that fold, and what must remain recoverable? | retain a positive reopening condition |
| OPEN | `CQ-RESIDUAL` | What is now the strongest unresolved relational difference, and which question actually separates it? | make the supported residual select the next program |

Every principal rhythm also carries the applicable anti-premature-closure questions:

| Compiled ID | Actual question |
|---|---|
| `CQ-WIDE-FIELD` | Which unresolved breakers, blockers, contradictions, similarities, and recurrences remain outside this local determination? |
| `CQ-COLLISION-SEPARATOR` | Which applicability, premise, role, path, or representation distinction separates the constraints that collided? |
| `CQ-PROPAGATE-RESIDUAL` | Which unresolved obligations mention the same conditions or roles, and what does this local return change for each of them? |
| `CQ-OVERLAP-RECURRENCE` | Does this recurring condition instantiate the same typed relation seen elsewhere, a new conjunction, or merely the same words? |
| `CQ-BLOCKER-CHAIN` | What missing representational, observational, computational, evidential, or authoritative capability blocks this relation, and can another method discharge it? |
| `CQ-LOCAL-CLOSURE` | What is closed only for this obligation, binding, horizon, and coverage, and what remains latent, blocked, reopened, or unsearched beyond it? |

The manifest stores the exact Coding source lines and the current v2.0-root lowering for each
compiled question. Those roots—`Expose`, `Orient`, `Factor`, `Polarize`, `Vary`, and `Ground`—remain
erasable hypotheses. They classify ordinary typed relation programs; they are not a fixed wheel or
successor primitives.

## The actual reciprocal challenges

The full default rhythm requires these opposed corpus pairs after an actual return. A challenge may
be absent only when that named challenge is individually recorded as typed but blocked.

| Movement | Forward/source question | Reciprocal/source question |
|---|---|---|
| constrain / release | 5710: Could the proposed condition disappear while the result remained? | 5714: Could the proposed condition remain while the result disappeared? |
| distinguish / coarsen | 6310: Why preserve this distinction? | 6326: Could the distinction disappear without any consequential loss? |
| maximal break / subtract | 5890: How far can the contrast be reduced before the answer is no longer forced? | 5898: What happens if that final distinction is removed? |
| factor / bypass / recompose | 5904: Through what, if anything, does the result follow? | 5912: Which part can be bypassed without changing the result? |
| orient / reverse | 5942: Why does the relation point in this direction? | 5944: Could the same established material support the reverse direction? |
| ground / withhold / defeat | 6190: What independently supports the relation? | 6100: What remains if every introduced interpretation is withheld? |
| fold / reopen | 6338: Why merge these possibilities? | 6352: Which future observation would reopen the merged class? |
| answer / next question | 6674: Which answer made another question unnecessary? | 6676: Which answer made a new question possible? |
| local closure / global residual | 6994: What is closed relative to the current frame? | 6996: What remains open beyond it? |
| remove / shaped hole / refill | 6058: Which removed part can be regenerated from what remains? | 6066: What happens if another filling occupies the same position? |

This is not “ask why twice.” Each pair acts on a different relation. In particular, the central
axes must remain distinct:

```text
CONSTRAIN <-> RELEASE       changes the admissible solution field
DISTINGUISH <-> COARSEN     changes the question/discrimination kernel
```

A discriminator may split alternatives without excluding either. A condition may exclude
alternatives without making them observationally distinguishable. The remaining pairs test path,
direction, support, regeneration, and answer-dependent succession.

The LLM may propose a method; the typed question determines what the method must return. Static

different discharge routes.

## Residual-selected rhythms

The harness does not cycle through all families. The active residual selects a principal rhythm:

| Residual | Selected rhythm |
|---|---|
| relational roles, scope, or applicability unclear | FRAME |
| several fillings remain or protected fillings are still merged | DISCOVERY |
| necessity, sufficiency, forcing, or boundary claim | BOUNDARY |
| explanation proposed or relation weakly supported | DETERMINATION / WHY |
| endpoint known but path, direction, order, or history unclear | PATH |
| concrete failure | FAILURE / REPAIR |
| representation too detailed or a fold is invalidated | COMPRESSION |
| implementation/domain substitution proposed | TRANSPORT |
| too many tests or questions | QUESTION BASIS |
| no more specific residual | DEFAULT SUCCESSOR CONSTRUCTION |

Every rhythm declares an exact compiled-question sequence, the reciprocal challenges that must be
represented or individually blocked, and the relational dimensions it must cover. A residual cannot
claim another rhythm merely because that rhythm is shorter.

## Adequate span and non-redundancy

For a substantial successor-construction pass, coverage is measured across:

```text
ADMISSIBILITY
DISCRIMINATION
PATH / DIRECTION / ORDER
ACTUALITY / SUPPORT
REPRESENTATION / REGENERATION
FRONTIER / ANCESTRY / REUSE
```

Many phrasings of one question do not increase this span. The validator derives family, dimension,
root, position, and source-line coverage from the selected compiled IDs; it rejects self-reported
coverage that does not match. It also rejects:

- using the predecessor recurrence as the active preformal rhythm;
- selecting a rhythm inconsistent with the declared residual;
- omitting one relational dimension required by the selected rhythm;
- replacing a compiled role/port inquiry with a same-surface field question;
- presenting one reciprocal movement as full closure;
- fabricating a corpus pair or calling a challenge blocked while still citing its pair;
- closing a raw return without a later accepted question-program occurrence; and
- detaching a stored occurrence from the exact policy active when it was recorded.

Passing these checks establishes structural use and relational variety only. It does not warrant an
answer, prove a root minimal, validate the temporary rhythm names, or promote any successor gate.

## Search-wide / commit-narrow state law

`PREFORMAL_SEARCH_ASYMMETRY.md` fixes two distinct scales:

```text
exploration scale  = large, contrasting, deliberately expansive
commitment scale   = small, warranted, exactly supported
```

A checked local relation is added to standing construction state, but only the residual regions it
actually resolves are removed. The remaining field persists as a topology of `active`, `blocked`,
`latent`, and `reopened` obligations with dependency and evidence ancestry. The root Frontier names
one strongest executable selection from that topology; it does not claim to enumerate the whole
unresolved universe.

After each local ratchet, the harness asks which other obligations reference the same condition or
role, propagates the new relation through them, and tests whether repeated paths are the same typed
relation, a new interaction, or surface recurrence. Contradictions generate separator questions.
Blockers generate capability-chain residuals. A local `Satisfied` state is always relative to its
obligation, binding, horizon, and coverage; it never means globally done.

## Rebuildable residual index

`RESIDUAL_OBLIGATIONS.json` is a stable seed of explicit project obligations, not moving state.
`ic-residual-topology.js` rebuilds a deletable index from that seed, the single active selection in
`IMPLEMENTATION_FRONTIER.md`, and schema-3 residual occurrences in the append-only trace. The
projection groups shared condition, breaker, blocker, and failed-fold coordinates into candidate
recurrence basins; those basins do not become methods or calculus relations until independently
checked. Deleting a generated projection loses no evidence or ancestry.

Question occurrences retain parent residual, condition, breaker, and reciprocal-obligation
coordinates. Residual occurrences retain parent/open relation, condition, blocker, breaker,
failed-fold, overlap, coverage, and next-family coordinates. This supports propagation without
turning the index into a second authoritative history.

## Demand-driven boundary incidence

The question-bank-derived exploration algorithm refines a shared coordinate into the normalized
key:

```text
schema @ bound-roles @ scope @ applicability @ grain @ orientation
```

Wording is absent from that identity. Two residuals share a condition only when these typed keys
are equal or a checked transport relation connects them. The rebuildable reverse incidence index
also tracks separators, breakers, survived contrasts, conflict cores, blockers, representation
gaps, failed-fold witnesses, and reopening conditions. It materializes only coordinates reachable
from an active or explicitly required residual; it does not enumerate every pair, basin, conflict,
or formal concept.

Every selected surface question records one disposition:

```text
Answered | Productive | Required | Redundant | Inapplicable | Blocked | Unknown
```

Every resolved completion field preserves one result class:

```text
Supported | Plural | ExactEmpty | Unsupported | Unknown | Blocked | ResourceBounded
```

`Expected` is inapplicable without a probability model. `Smallest`, `largest`, `strongest`, `best`,
and `cheapest` are inapplicable without their corresponding preorder, cost, strength, or preference
relation. Otherwise the query frontier remains nondominated over worst surviving block, leverage,
cost, risk, authority debt, and coverage gain rather than inventing a scalar score.

## Residual-shape method dispatch

Methods implement discharge patterns; their names are not semantics. The current derived dispatch
is ordered boundary to bisection/generalized binary search; decomposable breaker to delta
debugging; conjunctive conflict to QuickXplain/MUS; competing diagnoses to diagnosis plus
sequential discrimination; coarse abstraction to CEGAR; synthesis to CEGIS; finite partition to
partition refinement; unknown automaton to active automata learning; shared-condition basis to
attribute exploration; multi-context search to assumption-context management; and generic shape
to a nondominated applicable-method frontier. Every method must retain typed applicability,
expansion, provenance, failure exits, and reopening.
